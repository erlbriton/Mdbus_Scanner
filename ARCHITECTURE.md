# Техническая документация проекта Modbus Scanner (Android)

## 1. Назначение приложения
**Modbus Scanner** — специализированное высокопроизводительное Android-приложение, предназначенное для взаимодействия с промышленными контроллерами по протоколу Modbus RTU через USB-RS485/USB-Serial преобразователи.

Ключевой особенностью является адаптивная парсинг-система конфигурационных `.ini` файлов микроконтроллерных устройств для динамического формирования графического интерфейса и управления списком регистров.

---

## 2. Архитектурные принципы и жизненный цикл

### 2.1 Поведение Activity при повороте (No-Restart Lifecycle)
Для работы в полевых условиях на Android-планшетах/смартфонах запрещено перезапускать `MainActivity` и пересоздавать UI-дерево при смене ориентации экрана или изменении размеров окон.

Это достигается явной конфигурацией в `AndroidManifest.xml`:
```xml
android:configChanges="orientation|screenSize|smallestScreenSize|screenLayout"
```
Приложение обрабатывает адаптивность за счет Jetpack Compose без сброса состояния Modbus-соединения и открытых потоков данных.

### 2.2 Паттерн MVVM (Model-View-ViewModel)
* **View (UI Layer):** Строится на Compose (`ConfigScreen.kt`). Отвечает исключительно за визуализацию состояний и генерацию пользовательских событий.
* **ViewModel Layer (`MainViewModel.kt`):** Сохраняет UI-состояния (`pages`, `selectedPage`, `deviceId`, `isConnected`), управляет фоновыми корутинами опроса оборудования.
* **Data / Repository Layer:** 
  * `IniParser.kt` — парсер конфигураций устройств.
  * `ModbusRepository.kt` — слой абстракции работы с hardware-портом.

## 4. Детальный разбор реализуемой логики

### 4.1 Парсинг INI-файлов (`data/IniParser.kt`)
* **Кодировка:** Чтение файла происходит строго в кодировке `Windows-1251 (CP1251)`, так как конфигурационные файлы создаются в среде Windows для промышленных контроллеров. Чтение через `UTF-8` приведет к искажению кириллицы.
* **Структура `PageInfo`:**
  ```kotlin
  data class PageInfo(
      val id: String,          // Идентификатор (например: "p1000")
      val title: String,       // Название страницы (например: "Основные данные")
      val parameters: List<String> // Список параметров этой страницы
  )
  ```
* **Алгоритм разбора секции `[PAGES]`:**
  1. Строки читаются построчно с отслеживанием активной секции `[PAGES]`.
  2. Разделитель `=` отделяет ключ (`p1000`) от структуры значений.
  3. Разделитель `/` вычленяет заголовок страницы (текст до первого `/`) и перечень параметров (текст между первого и второго `/`, разделенный запятыми).

### 4.2 Отображение меню (`ui/ConfigScreen.kt`)
* Позволяет отобразить динамический вертикальный список страниц на базе `LazyColumn`.
* Каждая страница отображается в виде полноширинной кнопки `Button`.
* Цветом и формой кнопок можно управлять как локально через параметры `colors` (`containerColor`, `contentColor`) и `shape` (`RoundedCornerShape`), так и глобально через тему `MaterialTheme`.

### 4.3 Управление состоянием (`ui/MainViewModel.kt`)
* **`pages`**: Список загруженных из INI-файла объектов `PageInfo`.
* **`selectedPage`**: Страница, выбранная пользователем в данный момент.
* **`deviceId`**: Запрошенная строка идентификации микроконтроллера.
* **`loadIniFile(context, uri)`**: Метод, запускающий `IniParser` и выставляющий по умолчанию первую распарсенную страницу.
